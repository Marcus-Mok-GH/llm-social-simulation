# Umbra Station — LLM Social Simulation

A browser-playable social-deduction game where the other players are LLM-driven
agents. A human crew member moves around a space station with fog-of-war vision,
runs task minigames, reports bodies, and argues in meetings while AI agents
perceive, remember, reason, lie and vote. Built as a demonstration of
LLM-driven social simulation rather than scripted state machines.

## Run & Operate

- `pnpm --filter @workspace/llm-social-simulation run dev` — dev server (needs `PORT` and `BASE_PATH`)
- `pnpm --filter @workspace/llm-social-simulation run build` — production build to `artifacts/llm-social-simulation/dist/public`
- `pnpm --filter @workspace/llm-social-simulation run typecheck` — app typecheck
- `pnpm --filter @workspace/llm-social-simulation run check` — typecheck + all headless validators
- `pnpm --filter @workspace/llm-social-simulation run simulate` — headless full-match replays (no network)
- `pnpm --filter @workspace/llm-social-simulation run verify:llm` — live model check (needs a key)
- `pnpm run typecheck` — full workspace typecheck

Environment:

- `BERGET_API_KEY` — model key, exposed to the client through Vite `envPrefix`.
  Optional: without it the game runs on the scripted heuristic fallback.
- `VITE_LLM_BASE_URL`, `VITE_LLM_MODEL` — optional endpoint/model overrides
  (defaults `https://api.berget.ai/v1`, `mistral-small`).
- `DATABASE_URL` — not used by this artifact.

## Stack

- pnpm workspaces, Node 24, TypeScript 5.9
- React 19 + Vite 7, Tailwind 3, framer-motion, lucide-react
- HTML5 Canvas 2D rendering, A\* pathfinding over a derived grid
- Berget AI (OpenAI-compatible chat completions) for agent reasoning
- `localStorage` for match history; Convex schema stub is present but unused

## Where things live

- `artifacts/llm-social-simulation/src/game/engine.ts` — the whole match: phases,
  perception, kills, sabotage, meetings, voting, win conditions. No React, no
  wall-clock time; `tick(dt)` is the only way the world advances.
- `src/game/vision.ts` — line-of-sight test, visibility grid, ray-cast polygon,
  explored memory. Source of truth for "can this agent see that?".
- `src/game/perception.ts` — the agent's complete match log (append-only events,
  decisions and meetings) + suspicion vector.
- `src/ai/decision.ts` — the pluggable AI layer: node-graph serialization
  (current_location, valid_moves, visible_players, current_time) plus
  MOVE/VENT/SABOTAGE intents and meeting dialogue, with heuristic fallbacks.
  `src/ai/llm.ts` — transport, rate gate, JSON extraction.
- `src/game/map.ts` — the deck as data (rooms, corridors, points of interest).
- `src/game/zones.ts` — the spatial node graph: rooms and corridors as discrete
  zones, their adjacency, and `zoneAtPoint`/`zonePath`. AI movement is asked for
  as a destination zone, which the engine resolves with A* in `navigation.ts`.
- `src/game/events.ts` — the structured match timeline (kill / sabotage / repair
  / meeting / eject / verdict) the engine appends to as the match runs.
- `src/game/recap.ts` — pure `buildRecap`: turns that timeline plus the
  confessional into the end screen's "story of the shift" (beats, spotlight,
  closing quote). No engine, no clock, so it re-narrates identically.
- `src/components/GameStage.tsx` — canvas + engine loop + overlays; everything else is presentation.
- `scripts/simulate.ts` — the behavioural test that actually proves the game loop works.

## Architecture decisions

- **One tick function, no React inside the simulation.** The engine is plain
  TypeScript so `scripts/simulate.ts` can replay whole matches at 60 Hz and
  assert on outcomes. React renders a 10 Hz snapshot; the canvas runs per frame.
- **The fog is a bitmap plus a polygon.** Exact segment sampling answers
  "can A see B?" cheaply at 10 Hz, while a coarse raster + 360-ray polygon keeps
  the renderer fast enough to run every frame.
- **Votes are never generated by the model.** They are computed from each
  agent's suspicion scores, so what an agent says can be audited against what it
  believes. The model only chooses movement intents and meeting lines.
- **The recap is derived, never authored.** The engine banks structured events
  and the pure `recap.ts` writes the narrative from them, so the story always
  matches what actually happened and a saved match can be re-read later.
- **Every model call has a validated shape and a fallback.** A timeout, a rate
  limit, malformed JSON or an unsupported action all fall through to the
  heuristic, so the game never stalls waiting for a model.
- **The Skeld, credited.** The deck is The Skeld from Among Us (© Innersloth),
  ported as data in `src/game/map.ts` — 15 locations (14 rooms + Hallway), 7
  corridors as hubs, 14 vent grates in six chains, Reactor hand scanners and the
  Electrical lights panel. The official art (`public/skeld-map.webp`) is drawn
  as the deck itself, with the actors, task markers and fog on top (provenance
  noted in the artifact README). Station name, crew, roles, dialogue and the
  rest of the presentation remain original.

## Product

A single-player social-deduction round: pick a role, work the station, get
killed or catch the traitor, hold meetings, vote, and see the result written to
match history with the full transcript and every agent's belief snapshot.

## User preferences

- Build in `artifacts/llm-social-simulation` — that is the copy that deploys.
- The model backend is Berget AI; keep the endpoint OpenAI-compatible.

## Gotchas

- The Vite config throws without `PORT` and `BASE_PATH`; set both when running
  commands by hand.
- `bun` is required for the `scripts/*.ts` validators (pnpm runs the app).
- The API key is inlined into the production bundle at build time — see the
  deployment note in `artifacts/llm-social-simulation/README.md`.
- Run `run simulate` after touching anything in `src/game/` or `src/ai/`;
  balance changes are easy to make silently unwinnable.
- Agents are teleported (meeting seating, vent travel), so anything that
  relocates an actor must keep it inside walkable space. The engine has a
  safety-net snap for this, but new teleports should still use `seatAt`/
  `nearestStandable`.
